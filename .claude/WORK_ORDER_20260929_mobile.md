## 판정 기준 (지휘자 확정, 모바일 = 폭 ≤720px. 브레이크포인트는 기존 코드의 값을 재확인해 그대로 쓸 것)
1. **편집 화면 도크**: 메인 2개 = [핀 등록](기존 포인트 FAB) + [사진 등록](360 사진 등록: 기존 "360 사진 인입" 또는 "사진 폴더 일괄 매칭" 진입. 기존 함수 재사용). 나머지 6개는 [더보기 ⋯] 1개 → 바텀시트 서브메뉴로. 기존 기능은 하나도 삭제하지 않는다.
2. **뷰어 모바일**:
   - 상단 = 제목 + [닫기]만 항상 화면 안에 둔다(R1 필수).
   - 꼭지점 4개와 노트는 [⋯] 서브메뉴로.
   - 컨트롤 패드는 기본 접힘: [⋯ 도구] 1개로 펼치고, 버튼은 36px 이하.
   - 미니맵 툴바는 [접기/펼치기] 1개만 보이고 나머지는 서브메뉴로. 라벨 찌그러짐 제거.
   - 터치 기기에서는 힌트 문구를 터치용("드래그: 시점 · 두 손가락: 줌")으로 바꾼다.
3. 데스크톱(>720px)은 현행 유지(회귀 0). 터치 타깃 최소 32px, 대비 ≥4.5:1(UI 3:1).
4. **뷰어 기능 전수 검증** — 뷰어 버튼 21개(위 R1~R4의 id 전부) 각각에 대해 헤드리스 Chrome 375px에서 탭 → 측정 가능한 효과를 확인한다(카메라 yaw/pitch/fov 변화, 자동회전 플래그, 전체화면 요청, 마커 모드 진입, 목록 표시, 수평 보정 roll 값, reset 후 초기값 복귀, 미니맵 zoom 값, 닫기 후 overlay display:none). 결과는 표(PASS/FAIL + 측정값)로 낸다. FAIL은 근본원인을 고친다.
